# 프로젝트 개발 규칙 (Flowdesk Android)

## 🎨 UI/UX 디자인 시스템 및 상태 관리 표준 규칙

본 규칙은 Flowdesk Android 프로젝트의 일관된 UI/UX 톤앤매너와 사용자 경험을 유지하기 위한 표준 가이드라인입니다. 모든 신규 화면 개발 및 기존 화면 리팩토링 시 반드시 본 규칙을 준수해야 합니다.

---

### 1. 📱 화면 영역 제어 및 탐색 규칙 (WindowInsets & Navigation)
* **카메라 영역 침범 방지**:
  * 리스트 아이템 클릭 등을 통해 진입하는 모든 상세/수정/추가 서브 화면은 기기의 카메라 노치(Notch) 또는 카메라 홀 영역을 침범하여 레이아웃이 가려지지 않도록 **Window Insets 처리**를 적용해야 합니다.
  * Kotlin 코드 단에서 `ViewCompat.setOnApplyWindowInsetsListener`를 사용하여 상단 시스템 바만큼 패딩(`updatePadding(top = systemBars.top)`)을 동적으로 확보합니다.
* **하단 네비게이션 바 숨김**:
  * 메인 탭 화면이 아닌 상세/수정/추가 페이지 등 서브 화면에서는 화면 공간 확보와 집중도 향상을 위해 **하단 네비게이션 바(BottomNavigationView)를 보이지 않도록 제어**합니다.

### 2. 📝 상세/수정 입력 폼 디자인 규칙 (Layout & Input Style)
* **입력 폼 디자인 통일**:
  * 모든 상세 및 수정 화면의 입력 필드는 **테넌트 상태(시스템 관리) 편집 화면**(`fragment_status_edit.xml`)의 디자인 시스템을 기준으로 삼아 통일성 있게 구현합니다.
  * 기존의 테두리가 있는 사각형 박스 형태를 지양하고, **깔끔한 밑줄 스타일(Underline Style)**을 채택합니다.
* **필드 상세 스타일 지정**:
  * **EditText**: 배경 투명화(`android:background="@null"`), 글자 크기 `18sp`, 글자 스타일 굵게(`bold`), 글자 색상 `#0F172A`, 힌트 색상 `#CBD5E1`, 위/아래 안여백(`paddingTop="6dp"`, `paddingBottom="10dp"`).
  * **하단 구분선**: 각 입력 필드 바로 아래에 `1dp` 두께의 구분선(`View`, 배경색 `#E2E8F0`, `layout_marginBottom="28dp"`)을 배치하여 입력란 간의 간격을 정돈합니다.
* **필수 입력값 표시**:
  * 필수적으로 입력해야 하는 항목은 레이블 텍스트 우측에 **빨간색 별표(`*`)** 기호(`color="#EF4444"`, `bold`)를 명확히 표기하여 사용자가 인지할 수 있도록 유도합니다.

### 3. ⏳ 화면 로딩 상태 및 가시성 제어 규칙
* **상세/수정 화면 진입 시 로딩 상태 처리**:
  * 데이터 조회 API 호출이 완료되기 전(Loading 상태)에는 화면 내부에 빈 입력 필드나 기본 힌트(뼈대)가 노출되어 지저분하게 깜빡이지 않아야 합니다.
  * 로딩 중에는 **상단 타이틀바와 중앙 ProgressBar만 표시**하고, 입력 폼 영역(`ScrollView` 등)의 가시성은 기본적으로 **`View.INVISIBLE`**로 숨겨둡니다.
  * 데이터 로드가 완료되어 성공(`Success`) 상태에 도달하면 데이터를 뷰에 바인딩함과 동시에 `ScrollView` 등을 **`View.VISIBLE`**로 켜서 화면을 깔끔하게 한 번에 표출합니다.

### 4. 🔍 리스트 및 검색 영역 디자인 규칙 (List & Search Style)
* **검색바 스타일 통일**:
  * 모든 목록 화면의 검색 바(Search Bar) 영역은 **테넌트 상태(시스템 관리) 목록 화면**의 검색창 스타일과 구조를 그대로 참고하여 배치 및 구현합니다.
* **플랫(Flat) 스타일 목록 구성**:
  * 목록 내 리스트 아이템 카드(CardView 등)는 그림자(Elevation)가 과도하게 도드라지지 않고, 화면에 평평하게 밀착된 느낌의 깔끔하고 정돈된 **플랫(Flat) 디자인**으로 통일합니다.
* **더보기 버튼 및 아코디언 확장 메뉴**:
  * 목록 아이템 내 우측 정렬된 더보기 버튼은 **세로 점 세 개(⋮)** 모양 아이콘으로 통일합니다.
  * 더보기 아이콘 클릭 시, 팝업창이나 모달 다이얼로그를 띄우지 않고 **해당 카드가 아래 방향으로 부드럽게 세로 확장(TransitionManager 애니메이션 연동)**되며 내부에 `활성화 / 비활성화`, `삭제`, `수정` 등의 메뉴 버튼들이 노출되는 **아코디언 구조**를 기본으로 채택합니다.
* **상태 표시 배지**:
  * 목록 카드 내 활성/비활성 상태 배지는 **테넌트 상태(시스템 관리) 리스트의 배지 디자인**(폰트 크기, 둥글기, 배경 투명도 및 전용 테두리 등)을 참고하여 시각적 정체성을 맞춥니다.

### 5. 🗑️ 삭제 확인 및 경고 다이얼로그 규칙 (Custom Dialog)
* **커스텀 삭제 다이얼로그 사용**:
  * 목록 혹은 상세 화면에서 삭제 버튼을 누를 때 띄우는 알림 다이얼로그는 안드로이드의 기본 AlertDialog를 사용하지 않습니다.
  * **IP 차단 상세 정보 페이지에서 차단 해제 시 호출되는 프로젝트 커스텀 다이얼로그** 레이아웃의 형태 및 버튼 배치 스타일을 일률적으로 모방하여 시스템 전반에 일치된 디자인의 확인창을 노출합니다.

### 6. 🔄 등록 및 수정 완료 시 화면 전환 및 목록 동기화 규칙
* **등록 및 수정 완료 시**:
  * 추가(등록) 또는 수정 완료 성공 시 토스트 메시지를 표시하고, 즉시 **이전 목록 화면으로 복귀(`popBackStack()`)** 처리합니다.
  * 복귀 직전에 이전 목록 화면으로 리프레시 시그널(`findNavController().previousBackStackEntry?.savedStateHandle?.set("refresh", true)`)을 전달하여 목록이 최신 상태로 자동 동기화(새로고침)되도록 유도합니다.
